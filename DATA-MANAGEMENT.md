# thetangle.io — Data & Story Management

---

## Story Lifecycle

Every story moves through defined stages. Status is tracked in the story's JSON
metadata file and in the story planning doc.

```
idea → research → building → published → needs-update → archived
```

| Status | Meaning |
|---|---|
| `idea` | In IDEAS.md, not yet committed to |
| `research` | Data sources identified, model/approach being worked out |
| `building` | Active development — SvelteKit route + viz being built |
| `published` | Live on thetangle.io |
| `needs-update` | Published but data is stale or story needs revision |
| `archived` | No longer current — banner added pointing to newer version |

## Story Metadata Schema

Full schema for `src/content/work/{slug}.json`:

```json
{
  "slug": "foliage-2026",
  "title": "When Will the Leaves Turn?",
  "description": "A data-driven forecast of peak fall foliage across the Northeast.",
  "date": "2026-09-01",
  "lastUpdated": "2026-09-01",
  "dataRefreshedAt": "2026-08-28",
  "status": "published",
  "tags": ["environment", "forecast", "maps"],
  "ogImage": "/og/foliage-2026.png",
  "featured": true,
  "updateFrequency": "weekly",
  "archiveNote": null
}
```

`dataRefreshedAt` vs `lastUpdated`:
- `dataRefreshedAt` — when the underlying data was last fetched/reprocessed
- `lastUpdated` — when the story page itself was last changed (copy, design, etc.)

`archiveNote` — set when a story is archived:
```json
"archiveNote": "This forecast was for 2026. See the 2027 edition at /work/foliage-2027."
```

## Data Manifest (per story)

Every story's `data/` folder must have a `manifest.json`. This is the most important
organizational habit — without it, you'll forget in 6 months how the story was built.

```json
{
  "story": "foliage-2026",
  "lastProcessed": "2026-08-28",
  "files": [
    {
      "file": "predictions-2026.json",
      "description": "County-level predicted peak foliage dates for 2026",
      "source": "Generated by foliage prediction model",
      "pipeline": "birdland-pipelines/thetangle/foliage/predict.py",
      "s3Key": "thetangle-data/foliage-2026/processed/predictions-2026.json",
      "refreshedAt": "2026-08-28",
      "refreshFrequency": "weekly during Aug-Oct",
      "license": "derived work — see raw sources below"
    },
    {
      "file": "historical-averages.json",
      "description": "Historical average peak date by county, 2005-2024",
      "source": "USA National Phenology Network",
      "sourceUrl": "https://www.usanpn.org/data",
      "s3Key": "thetangle-data/foliage-2026/raw/usanpn-foliage-observations.json",
      "fetchedAt": "2026-07-15",
      "refreshFrequency": "once — historical data does not change",
      "license": "CC0 — public domain"
    },
    {
      "file": "counties.geojson",
      "description": "Northeast US county boundaries",
      "source": "US Census TIGER/Line 2024",
      "sourceUrl": "https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html",
      "s3Key": "thetangle-data/shared/counties-northeast.geojson",
      "fetchedAt": "2026-07-10",
      "refreshFrequency": "annually or when Census updates",
      "license": "Public domain"
    }
  ]
}
```

## S3 Bucket Structure

Raw source data and processed outputs are always separate. You can reprocess from raw
without re-fetching. Never modify files in `raw/`.

```
s3://thetangle-data/
  shared/                         ← reusable across stories (GeoJSON, shapefiles, etc.)
    counties-northeast.geojson
    states-us.geojson

  foliage-2026/
    raw/                          ← source data exactly as fetched, never modified
      usanpn-foliage-observations.json
      prism-temps-northeast-2005-2026.csv
      us-drought-monitor-2026.json
    processed/                    ← model outputs, ready for site to consume
      predictions-2026.json
      historical-averages.json

  [next-story]/
    raw/
    processed/

s3://thetangle-assets/
  og/                             ← OG preview images
  social/                         ← social share screenshots by format
    foliage-2026/
      landscape.png
      square.png
      vertical.png
```

## Local Development Structure

Local `data/` folders mirror S3. Small files (<1MB) are committed to git.
Large files are `.gitignore`d with a fetch instruction in the manifest.

```
src/routes/work/foliage-2026/
  +page.js
  +page.svelte
  components/
    FoliageMap.svelte
    CalendarStrip.svelte
  data/
    manifest.json           ← always committed
    predictions-2026.json   ← committed if small enough
    historical-averages.json
    counties.geojson        ← gitignored if large, fetch from S3
    .gitignore
```

`.gitignore` in each story's `data/` folder:
```
# Large files — fetch from S3
counties.geojson
*.csv
```

## Story Changelog

Each story planning doc (`stories/{slug}.md`) gets a changelog section.
Update it whenever the story or its data changes after publish.

```markdown
## Changelog

| Date | Change |
|---|---|
| 2026-09-01 | Published |
| 2026-09-08 | Data refreshed — weekly model rerun |
| 2026-09-15 | Data refreshed — added drought stress layer |
| 2026-10-20 | Archived — 2026 season ended, added link to 2027 edition |
```

## Checklist: Starting a New Story

- [ ] Create `stories/{slug}.md` planning doc with status `research`
- [ ] Add entry to `IDEAS.md`
- [ ] Create `src/content/work/{slug}.json` metadata file with status `research`
- [ ] Create `s3://thetangle-data/{slug}/raw/` and `/processed/` prefixes
- [ ] Create `src/routes/work/{slug}/data/manifest.json` as sources are identified
- [ ] Update story status to `building` when development starts
- [ ] Update `dataRefreshedAt` in metadata whenever data pipeline runs
- [ ] Add changelog entry on publish

## Checklist: Updating a Published Story

- [ ] Update data pipeline, write new processed files to S3
- [ ] Update `dataRefreshedAt` in `src/content/work/{slug}.json`
- [ ] Update `manifest.json` with new `refreshedAt` timestamps
- [ ] Add changelog entry in `stories/{slug}.md`
- [ ] Trigger Amplify rebuild (or let pipeline webhook handle it)
