# thewildplot.io — Architecture Notes

## Backend Data Strategy

### Existing AWS Infrastructure (Birdland Metrics)
- Lambda functions in `mlb-daily-pipeline` Step Function
- S3 buckets: `mlb-elo-ratings-output` (JSON/CSV outputs)
- Data: ELO ratings, playoff odds, standings, schedule, player stats, WAR projections

### thewildplot.io Data Pattern
- Story data is pre-generated by Lambda and written to S3 as JSON
- SvelteKit fetches from S3 **at build time** via `load()` in `+page.js`
- Output is baked into static HTML — no client-side fetching
- When data updates: Lambda → S3 → Amplify rebuild webhook → fresh static deploy
- New story pipelines deploy under `thewildplot-*` prefix in existing AWS account

## Story Codebase Structure (Option C — Hybrid)

### Principle
- Each story is a **fully custom SvelteKit route** — no constraints on viz or layout
- A **JSON metadata file** per story drives the work index automatically
- A **story registry** (`src/lib/stories/index.js`) imports all metadata — index page reads from it
- Data fetching happens **at build time only** via `+page.js` load functions — no client-side fetching
- Each story declares its own data needs; demands vary per story

### Directory Layout
```
src/
  lib/
    stories/
      index.js              ← registry: imports + exports all story metadata
    components/
      Nav.svelte
      Footer.svelte
      OgMeta.svelte
      ScrollCard.svelte     ← reusable floating narrative card for scrollytelling
  routes/
    work/
      +page.svelte          ← work index — reads from story registry
      foliage-2026/
        +page.js            ← load(): fetches story data from S3 at build time
        +page.svelte        ← full custom story page, receives data as props
        components/
          FoliageMap.svelte
          CalendarStrip.svelte
      [next-story]/
        ...

src/content/work/
  foliage-2026.json         ← story metadata (title, description, date, tags, ogImage)
  [next-story].json
```

### Story Metadata Schema (`src/content/work/foliage-2026.json`)
```json
{
  "slug": "foliage-2026",
  "title": "When Will the Leaves Turn?",
  "description": "A data-driven forecast of peak fall foliage across the Northeast.",
  "date": "2026-09-01",
  "tags": ["environment", "forecast", "maps"],
  "ogImage": "/og/foliage-2026.png",
  "featured": true
}
```

### Story Registry (`src/lib/stories/index.js`)
```js
import foliage from '$content/work/foliage-2026.json';
// import nextStory from '$content/work/next-story.json';

export const stories = [foliage];  // ordered by recency
```

### Build-Time Data Fetching (`+page.js`)
```js
// src/routes/work/foliage-2026/+page.js
export async function load({ fetch }) {
  // Runs at build time — baked into static HTML, zero client-side fetching
  const [predictions, historical] = await Promise.all([
    fetch('https://s3.amazonaws.com/thewildplot-data/foliage/predictions-2026.json').then(r => r.json()),
    fetch('https://s3.amazonaws.com/thewildplot-data/foliage/historical-averages.json').then(r => r.json()),
  ]);
  return { predictions, historical };
}
```

### Data Fetch Patterns by Story Type

| Story type | Data source | Fetch pattern |
|---|---|---|
| Static / archival | JSON in repo | Direct import in `+page.js`, no fetch needed |
| Seasonal forecast (e.g. foliage) | Lambda → S3 JSON | `load()` fetches S3 at build time; Amplify rebuild on data update |
| Live / frequently updated | Lambda → S3 JSON | Same as above + more frequent Amplify rebuilds via EventBridge webhook |

### Amplify Rebuild Trigger (for data-driven stories)
- Lambda writes updated JSON to S3
- S3 event notification → Lambda → calls Amplify `StartJob` API
- Amplify rebuilds site → fresh static HTML with new data baked in
- No client-side fetching required at any point

## Migration Path: If SSR Is Needed Later

### Option 1 — Amplify Hosting Compute (simplest)
Amplify has a built-in SSR tier — no ECS, no ALB, no new infrastructure.

1. Swap adapter in `svelte.config.js`: `adapter-static` → `adapter-node`
2. Redeploy to Amplify — it auto-detects SSR and switches to compute tier
3. Done. Route 53 and domain config unchanged.

Cost: pay-per-request compute on top of existing Amplify costs. Cheapest SSR option, least control.

### Option 2 — Fargate (full control)
1. Swap adapter: `adapter-static` → `adapter-node`
2. Write Dockerfile (~15 lines — node:20-alpine, copy build, `node build/index.js`)
3. Create ECR repo, push image
4. Create ECS cluster + Fargate task + ALB + target group
5. Update Route 53: swap Amplify alias → ALB DNS name
6. Replace Amplify CI/CD with GitHub Action: push → ECR → `ecs update-service`
7. Disconnect Amplify

Cost: ~$25-30/month (ALB ~$16-18 + Fargate compute ~$9-10). Half-day of work given existing AWS familiarity.

### Recommendation
Start with `adapter-static`. If SSR becomes necessary, try **Amplify Compute first** — it's a one-line swap with no infrastructure change. Only move to Fargate if you need more control (custom headers, edge logic, longer request timeouts, etc.).

## Illustration & SVG Workflow

Three tiers depending on the asset type:

**1. Simple geometric assets — write as code**
Timeline bars, grids, zone backgrounds, annotated diagrams. These are writable as raw
SVG markup. Describe what you need to an LLM and get SVG code back, or write by hand.
Drop the `.svg` in `static/assets/{story}/` and reference in Svelte. No design tool needed.

**2. Illustrative / decorative art — Recraft**
Recraft (recraft.ai) generates native vector SVG output from text prompts — real paths
and fills, not raster-converted. Best for warmer, illustrative pieces (Tracking Theo,
scene-setters). Free tier available. Figma plugin exists for further refinement.

**3. Data visualizations — D3.js in code**
All data-driven graphics are built in D3. No design tool involved. The D3 output IS
the illustration.

**Decision rule:** Does this change based on data or user input?
- Yes → D3 (generated in browser from data)
- No, but illustrative → Recraft (prompt → native SVG → drop in static/)
- No, geometric → write SVG by hand or with LLM help

**Coexistence pattern:** Static SVG assets sit in the background. D3 draws on top via
`position: absolute`. The static asset is the visual frame; D3 supplies the data layer.

**Figma** is useful for complex multi-element compositions too fiddly to write by hand
and too specific to prompt. Not needed for the current story queue — defer until a
story clearly requires it.

### SVG Animation

Animating SVG assets (e.g. character motion for Tracking Theo) requires the SVG to
have moving parts as **separate named elements** with IDs. If Recraft merges everything
into one path, open the file in Figma or Inkscape first and separate the parts.

Three animation approaches by complexity:

| Approach | Use when | Tool |
|---|---|---|
| CSS `@keyframes` | One-time, simple rotation/translate, not scroll-driven | CSS |
| GSAP + ScrollTrigger | Scroll-driven motion, single or few elements | `gsap`, `gsap/ScrollTrigger` |
| Rive | Multi-part character animation, natural motion, state machines | `@rive-app/canvas` |

**GSAP pattern (scroll-driven):**
```js
gsap.to('#father-arm', {
  rotation: -25,
  transformOrigin: '120px 80px',  // shoulder pivot in SVG coords
  scrollTrigger: {
    trigger: '#scene',
    start: 'top center',
    scrub: true   // motion tied directly to scroll position
  }
});
```

**CSS caveat:** `transform-origin` on SVG elements uses SVG coordinate space, not
percentages — set the pivot point in px matching the SVG viewBox coordinates.

**Rive** is the right choice for Tracking Theo specifically — the warmth of that
story requires natural character motion that CSS/GSAP rotation alone can't produce.
Rive lets you rig joints, set bone hierarchies, and build animation state machines.
Web runtime integrates with SvelteKit via `@rive-app/canvas`. Free tier sufficient.

## Social Screenshot Pipeline

See `SOCIAL-PIPELINE.md` for full detail.

- Playwright Lambda (`thewildplot-screenshots`) visits `/share/*` routes per story
- Captures 4 formats: landscape (1200×628), square (1080×1080), portrait (1080×1350), vertical (1080×1920)
- Stores to `s3://thewildplot-assets/social/{slug}/{format}.png`
- Triggered by Amplify build webhook after each deploy
- Each story defines its own share routes — intentionally designed frames per aspect ratio
- **Font fidelity**: self-host all fonts, `document.fonts.ready`, `deviceScaleFactor: 2`, `--font-render-hinting=none`
- Backport font fixes to Birdland `mlb-og-screenshots` Lambda (see SOCIAL-PIPELINE.md)
